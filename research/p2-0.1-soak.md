# P2-0.1 七天数据观察日志

第一观察周期：从批准部署的那一刻起 **连续 7 天**。
检查方法见 `docs/p2-0.1-audit.md` §8——全部走 Dashboard 的只读接口
（`http://<NAS-LAN-IP>:8787`），**不 SSH、不 `docker exec`、不打开 `.duckdb`**。

> 本文件的成功标准不是 ACCEPT 变多，而是**没有未解释的数据洞**。
> 发现异常：先记录证据，再定位原因。不允许清库、放宽阈值或隐藏异常。

| 磁盘剩余 | 91.81% |
| Shadow DB | **不可得**（生产心跳尚无该字段） |

两点必须记在案：

1. **`DATA_UNAVAILABLE = 18,370` 从 18:12 到 18:55 一次都没有增长**，而同期
   `evaluated` 从 142,714 涨到 173,602。它是**这一轮运行早期的一次性事件留下的**，
   不是正在发生的数据中断。原因未定位——这是观察期要解释的第一件事。
2. **`accept_scope`（独立市场 / 独立 Token / 重复次数）在部署前拿不到**：
   生产报表尚无该字段。也就是说，部署在换来源码能力的同时，**也会丢掉
   "这 10,960 次 ACCEPT 到底覆盖多少个独立市场"这一信息**——它只能在部署之后
   重新累计。这是"现在部署"与"等观察期开始"之间唯一实质性的取舍。

## 统计口径（重要）

所有决策计数都是**当前 Shadow 运行**口径（`totals.window = "cumulative for the
current run"`），**Shadow 每重启一次就归零**。因此：

- 任何跨天结论必须写明“含 N 次重启”，或者只用**单次连续运行**内的子样本；
- 在实现跨重启累计口径之前，**不要**把多段运行的 ACCEPT 直接相加当成“7 天累计”。

## 退出条件

连续 7 天同时满足：

1. 无未解释的数据洞（`data_gaps` 与 `errors` 的每次增长都有记录在案的原因）；
2. 无 checkpoint 停滞（盘口场地时间戳始终在前进）；
3. 无容器非预期重启；
4. `accept_scope` 已积累到可支撑“独立市场 × 目标日”级别样本量。

满足后才讨论模型评估与模拟交易阶段。注意 P2 的前提“**模型样本外有效**”
**仍未满足**（`research/baseline-comparison.md`：Brier 1.49 vs 市场 1.03）——
本轮工作不会让模型变好，只会让数据可信。

## 观察期内禁止

真实下单、钱包 / 私钥、自动交易、修改阈值或模型参数、清库 / 重建、伪造历史数据、
在生产环境跑破坏性测试。**为测试便利而重启生产容器同样算中断采集，需要单独批准。**
